## 三、真实用户名登录/绑定窗口准入条件（还未执行）

**禁止仅凭模拟测试通过就打开真实登录。** 需要明确的独立 Staging 测试范围与用户批准，以及以下项目：

1. 复核生产/测试项目 ID 与所有 Git Blob SHA，并做测试前只读总量快照（Auth 用户数、alias 数、owner_probe 数、限流行数）。
2. 复核核心安全顾问、密码泄露保护和对公开登录函数的限流/防洪泛能力。当前 Staging Advisor 仍提示 `auth_leaked_password_protection` WARN，注册必须继续关闭。无可管理 Cloudflare Zone 时不能假称已部署 WAF。
3. 预设**短于或等于 15 分钟**的精确 UTC 开始/结束时间，固定在 Staging Edge 源码中；任何缺失条件默认拒绝。`N10A6_STAGING_ENABLED` 只在明确批准和最终检查后短暂生效。代码中保留 1970 旧状态的可审核回滚副本。
4. 先以公开 `preflight` 确认 **enabled=false**，在已批准时间窗内才确认 `enabled=true`；窗口内绝不开放注册（`registration_enabled=false`）。
5. 使用现有 Staging QA 测试账户，不传输密码、JWT、验证码、邮箱到聊天。先验证已有 alias 的用户名+密码 → 同一 Auth UID（含 `getUser` 和 `getSession`）→ 仅自身 RLS owner probe。使用**新** Cloudflare token，各请求不复用。
6. 针对未绑定的第二既有 Staging QA 用户，只有在用户允许、现有 email/Google 会话 UID 已验证时才绑定；测试用户名唯一、重复拒绝、错误密码、登出与换账号；不创建新的 Auth 用户，不修改现有财务业务。
7. 对照测试前后用户数、UID 与 RLS/username alias 数（新增 alias 仅应等于测试中明确授权的绑定数）。
8. 真实截止时刻应自然回到 `preflight enabled=false` 与 login/bind 503。随后恢复环境开关 false，并重新部署硬编码 `CODE_GATE_OPEN=false` 和 1970 时间窗以完整回归冻结状态，重复上述 3 项 HTTPS 关闭测试。
9. 任何状态错乱、身份不一致、账号枚举、账户授权失败、请求异常、出现可疑流量，立即停止并安全关闭；**绝不删除账号/用户名映射/RLS/财务记录以“回滚”**。
