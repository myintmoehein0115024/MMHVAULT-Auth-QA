## 五、生产 RLS 与安全顾问（真正只读）

- 生产 `get_advisors(security)` 发现 2 条 WARN：
  1. `authenticated_security_definer_function_executable`：`public.mmh_delete_crypto_wallet_movement_v4(p_id uuid)` 允许 `authenticated` 执行，函数由 postgres 拥有、`SECURITY DEFINER`；只读查看源码后已确认它先取 `auth.uid()` 并使用 `user_id=auth.uid()` 限定钱包移动记录、关联投资、交易删除，显然是有意实现与单用户记账相关。**不应未经完整越权回归便撤销 EXECUTE 或改 SECURITY INVOKER**；仍需两个用户和恶意 ID 的真正负面测试后才能解除风险阻断。
  2. `auth_leaked_password_protection`：生产未启用泄露密码检查，需在用户确认的生产安全配置变更窗口单独开启并复核兼容。
- 审查了生产 35 张 Accounts/Transactions/Invest/Goals/Budgets/Life Planner 等有关表：**均有 RLS、均有至少 1 条策略**。
- 进一步抽查十张关键表的共 40 条 SELECT/INSERT/UPDATE/DELETE 策略：**40/40 均包含 `auth.uid()` 所有者约束**，未看到 `USING true` / `WITH CHECK true`。
- 这些属于静态控制审查；**不能代替生产等价环境内使用两个用户进行恶意 UID / ID 的真实 RLS 越权验证**。不得把这项静态 PASS 改称为最终全站数据隔离 PASS。
