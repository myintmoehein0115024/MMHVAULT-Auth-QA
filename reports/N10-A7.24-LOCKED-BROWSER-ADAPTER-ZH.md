## 一、浏览器适配器的职责

为之前的 `N10-A7.23` 受控验收流程提供 Supabase SDK 返回值转换和后台接口包装，但**不内置、也不加载任何生产或 Staging 账号密码**。代码仅提供可以在未来经过审核后注入依赖的函数，不是已经上线的网站。

具体条件：
1. 完整固定 Staging ID `ldivswlhtgmznzwhzsoi`、`https://ldivswlhtgmznzwhzsoi.supabase.co`、`/functions/v1/mmh-n10a6-username`、GitHub QA 来源；任何配置错配返回 `wrong_project_or_client`。
2. 只接受 `sb_publishable_...` 公钥格式。**不能使用 service-role、secret key**。
3. `preflight`、`bind`、`login` 只 POST 到固定 Staging Edge，禁止携带 cookie（`credentials:'omit'`），不在查询字符串中附加 JWT、密码或验证码，禁止更换 Edge URL。
4. `auth.getUser()` 读取 `result.data.user`、`auth.getSession()` 读取 `result.data.session`；任何 SDK `error` 必须拒绝。不能把 OAuth/Email 显示名称、用户可编辑 metadata 当安全身份依据。
5. `ownerProbe` 仅对 `mmh_n10a6_auth_owner_probe` 请求 `user_id`，最多两条返回；再由 N10-A7.23 验收控制器检查恰好 1 条、其 UID 与 Auth 远程/本地 UID 全一致。
6. **绑定前**再检查 `getUser`、`getSession` 同 UID、已验证邮箱、非匿名账户及 owner_probe，之后仅向受保护 Edge 提交带当前 Bearer 的绑定请求。
7. 用户名登录的 `access_token/refresh_token` 只在内存中交给同一 Staging SDK 的 `setSession`，随后由 N10-A7.23 的流程再次执行真实 `getUser/getSession/RLS`。适配器不做任何跳转、设备授权或财务读写。
8. `signOutLocal()` 严格使用 `scope:'local'`，发现 SDK `error` 不可假装退出成功。
9. 此文件不访问浏览器 Local/Session Storage、不使用全局 `fetch`，也不初始化实际 Supabase Client；未来真实网页需另外审查仅当前标签页 storage、禁用 OAuth 自动 URL 会话检测、防止页面跳转带入其他项目令牌、会话销毁与 CSP。
