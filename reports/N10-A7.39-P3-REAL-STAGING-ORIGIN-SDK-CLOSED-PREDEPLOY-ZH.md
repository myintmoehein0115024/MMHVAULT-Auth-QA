## 2. 真实 Edge v11 的 4 项精确、可逆候选改动

源文件：`review/N10-A7.39-P3-STAGING-EDGE-CORS-SDK-CLOSED-NEVER-DEPLOY.ts`

从**云端读回的实际 v11 完整源码**派生，且对全部差异逐项反向还原后与实际 v11 源码逐字一致，仅有四组改动：
1. `ORIGIN` 从原 GitHub QA 改为新的 Access 私有 QA Origin；
2. `HOSTNAME` 从旧 GitHub QA 改为新的 Cloudflare 私有 QA Turnstile hostname；
3. 未经授权的 `OPTIONS` 预检改为直接 **403 origin_not_allowed**，合法 QA Origin 仍为 204；
4. `Access-Control-Allow-Headers` 从 `content-type,apikey,authorization` 改为 `content-type,apikey,authorization,x-client-info,x-retry-count`。

增加 `x-client-info` 是依据当前 Supabase SDK 的浏览器 CORS 文档：SDK 某些请求会自动携带该标头，原始手写 Edge 头会阻断 SDK 类型的 CORS 预检。保留了**精确允许 Origin 和有限标头清单**，没有设 `Access-Control-Allow-Origin: *` 或允许跨站 Cookie。

Supabase 官方文档：
https://supabase.com/docs/guides/functions/cors

候选保持 `CODE_GATE_OPEN=false`、1970 年失效窗口、Secret gate、Staging-only 项目号、密码证明、原 UID / RLS Owner Probe、用户名唯一性、原验证码 hostname/action 严格验证、HMAC 一次性 Token、限流和本地退出逻辑不变。
