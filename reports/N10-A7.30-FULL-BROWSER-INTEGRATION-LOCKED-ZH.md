## 三、新增浏览器协调器的安全语义

- 默认 `ALLOW_BROWSER_ACCEPTANCE=false`，所有输入都不能改变默认硬锁，且锁定时不初始化 SDK、Widget 或网络请求。
- 固定独立 Staging Project/Endpoint/Origin，只接收 `https://myintmoehein0115024.github.io` 作为合成 QA Origin；`mmhvault.com` 与 `www.mmhvault.com` 均不能私自成为 Staging 来源。
- 需要未来的、格式严格且尚未到期的 UTC deadline；本地额外时间检查**不能替代**服务端 Edge 预检/硬锁。浏览器自己的时钟并不构成权威的云端开窗保障。
- 一个协调器实例只能运行一次，禁止重复调用或并发重复提交，避免验证码复用和绑定副作用。
- 必须先创建隔离 SDK，再创建受限 Adapter、单独 CAPTCHA，最终执行原 N10-A7.23 合约；未通过任一模块的配置或依赖校验均 Fail-Closed。
- 无论成功或失败，finally 关闭 Turnstile Widget 并调用 SDK close()。只要 SDK 清理返回不确定或抛异常，必须将验收改为 `session_cleanup_unconfirmed`，**不可把先前的登录成功视为最终 PASS**。
- 返回给 UI 的结果只含白名单错误码和内部步骤名，不包含邮箱、密码、UID、JWT、refresh token 或 Turnstile token。

### 需要注意的限制

- 浏览器页面仍是 N10-A7.26 默认锁定的展示 UI，全部真实结果是 `NOT RUN`，账号与密码字段 disabled。合成测试调用的临时执行接口只存在于 CI 内存 bundle，不连接用户输入。
- 真实 SDK + 合成服务器成功**不等于**真正的 Supabase Staging Auth 服务器、真实 RLS 隔离、Google OAuth 或真实 Cloudflare Siteverify 完成端到端验收。
- GitHub Pages 静态 HTML meta CSP 与真正响应级 CSP/HSTS/iframe 防护不同；未来公开输入密码的受控验收界面，需要另行审核安全托管、实际响应头及 CDN 的静态脚本完整性。不要通过向当前锁定 QA 页面直接加明文账号输入绕过审批。
- Local signout 和 Map 清空不能保证先前发出的 Access JWT 立即被所有后端拒绝；未来需要考虑 TTL、服务端会话撤销及权限保护。
- 合成注入使用了虚构 Publishable Key、虚构邮箱、虚构 UID、虚构密码、虚构 JWT；它们不具有连接真实 Supabase Auth 的能力。正式 Secret 没有被接触。
