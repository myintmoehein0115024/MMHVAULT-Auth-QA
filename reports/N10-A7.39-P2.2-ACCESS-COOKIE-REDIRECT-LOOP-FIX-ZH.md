# MMHVAULT — N10-A7.39-P2.2 Cloudflare Access 重定向循环修复报告

日期：2026-10-29 UTC。

## 故障证据

用户提供 Google Chrome 无痕模式截图，访问 `mmhvault-auth-g10g11-locked.pages.dev` 后显示 `ERR_TOO_MANY_REDIRECTS`，表示 Cloudflare Access 与 QA 主机之间出现循环重定向。截图不能单独确定某一个根因。

实际通过已连接 Cloudflare API 只读读取发现，两个应用 `same_site_cookie_attribute='strict'`：
- `mmhvault-auth-g10g11-locked.pages.dev`
- `*.mmhvault-auth-g10g11-locked.pages.dev`

Cloudflare 官方文档直接指出：出现 `ERR_TOO_MANY_REDIRECTS` 时应检查 SameSite 并设置为 `None` 或 `Lax`；`Strict` 可能导致循环。

官方来源：https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/#samesite-attribute

## 经用户报告故障后执行的最小修复

保持应用的确切域名、类型、原政策 ID、原两条精确邮箱授权、策略顺序、15 分钟 Session、HttpOnly=true、Binding Cookie=true、Eager Redirect Cookie=true、Options Preflight Bypass=false，分别对两个非生产 QA Access 应用进行最小必要更新：

- 主域名 Access 应用 `e0debc2e-8637-4db0-ac4a-c25beabde850`，`same_site_cookie_attribute: strict → lax`，HTTP 200，GET 校验成功。
- 版本别名 Access 应用 `5acd4e87-c126-4a4a-ac47-8b0a91b14ab8`，`same_site_cookie_attribute: strict → lax`，HTTP 200，GET 校验成功。

修复没有修改/扩展任何 Access 允许的邮箱；应用仍均只有 **2 条 Allow policy，每条只匹配完整指定邮箱**，没有 Everyone、Email Domain、Bypass 或其他放行条件。不在公开 GitHub 报告里写入私人邮箱明文。

**判断限定**：从 Cloudflare 实际配置和官方文档可确认 `Strict` 是一个已知会导致重定向循环的因素，现已修复；但没有代替用户使用其 Access 身份完成浏览器登录，因此不能声称所有浏览器的重定向问题已完全解决。
